# Batch 22 Korean editorial drafts

## pdf-watermark
- **소개와 원리:** 입력한 문자열을 모든 PDF 페이지 가운데에 30pt 회색 반투명 글자로, -30도 기울여 그립니다. 입력이 비어 있으면 `Woori Tools`를 사용합니다.
- **활용과 절차:** 초안임을 표시할 문서를 선택하고 워터마크 문구를 입력한 뒤 실행해 새 PDF를 확인합니다.
- **예제:** `검토용`을 입력하면 모든 페이지 중앙에 같은 문구가 표시됩니다.
- **결과 해석:** 워터마크는 별도 PDF의 실제 페이지 내용으로 추가되며 원본은 변경하지 않습니다.
- **제한 및 FAQ:** 위치·각도·크기·투명도는 고정이고 문구가 길면 페이지 밖이나 기존 내용 위에 놓일 수 있습니다. 빈 문구는 기본 문구가 사용됩니다.

## pdf-metadata-viewer
- **소개와 원리:** PDF의 제목, 작성자, 주제, 키워드, 페이지 수, 제작자 필드를 읽어 표시합니다.
- **활용과 절차:** 문서 관리 정보를 확인하려면 PDF를 선택하고 실행합니다.
- **예제:** 제목 `회의록`, 작성자 `Mina`, 4쪽 PDF라면 해당 필드와 페이지 수 4가 결과에 표시됩니다.
- **결과 해석:** 값이 없는 표준 필드는 대시로 나타납니다. 페이지 수는 파일의 페이지 트리에서 읽습니다.
- **제한 및 FAQ:** XMP나 사용자 정의 메타데이터 전체를 탐색하지 않습니다. 문서 속성을 모두 보여주나요? 아니요, 나열된 기본 필드만 표시합니다.

## pdf-remove-metadata
- **소개와 원리:** 제목, 작성자, 주제, 키워드, 제작자, 생성 프로그램의 표준 PDF 문서 정보 값을 비웁니다.
- **활용과 절차:** 공유 전에 이 필드들을 제거하려면 파일을 선택해 처리하고 새 PDF를 내려받습니다.
- **예제:** 메타데이터 뷰어에서 제목 `회의록`, 작성자 `Mina`로 보이던 파일을 처리하면 해당 필드는 빈 값이 됩니다.
- **결과 해석:** 페이지 내용과 수는 유지되고 표준 필드만 지운 별도 파일이 생성됩니다.
- **제한 및 FAQ:** XMP 패킷, 주석, 사용자 정의 데이터 등 모든 잠재 메타데이터를 제거한다고 보장하지 않습니다. 사진 내용도 바뀌나요? 아니요.

## json-to-yaml
- **소개와 원리:** 유효한 JSON을 파싱한 뒤 값 구조를 YAML 문서로 직렬화합니다.
- **활용과 절차:** 설정 데이터를 YAML 형식으로 옮길 때 JSON을 붙여넣고 실행합니다.
- **예제:** `{"service":"api","enabled":true}`는 `service: api`와 `enabled: true` 항목을 가진 YAML로 바뀝니다.
- **결과 해석:** 키와 문자열·숫자·불리언 값 구조를 유지합니다. 따옴표나 공백 모양은 출력 규칙에 따라 달라질 수 있습니다.
- **제한 및 FAQ:** 잘못된 JSON은 변환되지 않습니다. 주석을 보존하나요? 입력은 JSON이므로 주석이나 원래 서식을 보존하지 않습니다.

## yaml-to-json
- **소개와 원리:** YAML 문서 하나를 파싱해 2칸 들여쓰기의 JSON으로 출력합니다.
- **활용과 절차:** YAML 설정을 JSON 기반 도구에 전달하려면 문서를 붙여넣고 실행합니다.
- **예제:** `service: api`와 `enabled: true`는 `{"service":"api","enabled":true}` 구조로 표현됩니다.
- **결과 해석:** YAML 값은 JSON 자료형으로 변환되며 결과는 읽기 쉽게 줄바꿈됩니다.
- **제한 및 FAQ:** 잘못된 YAML이나 여러 문서가 들어 있는 입력은 처리되지 않습니다. 주석과 서식은 JSON 결과에 남지 않습니다. 주석도 변환되나요? 아니요.
