# Batch 23 Korean editorial drafts

## csv-to-json
- **소개와 원리:** 첫 행을 객체 키로, 각 다음 행을 객체 하나로 읽습니다. 구분자는 자동 감지하고 빈 줄은 건너뛰며 숫자와 참/거짓 값은 가능한 경우 자료형으로 변환합니다.
- **활용과 절차:** 표 데이터를 JSON API에 전달하려면 헤더가 있는 CSV를 붙여넣고 실행합니다.
- **예제:** `name,active,count` 다음에 `Mina,true,3`을 넣으면 이름 문자열, 참 값, 숫자 3을 가진 객체 배열이 나옵니다.
- **결과 해석:** 첫 줄은 필드명이므로 데이터 행으로 반환되지 않습니다. 출력 JSON은 두 칸 들여쓰기입니다.
- **제한과 FAQ:** 모든 행은 호환되는 열 수를 가져야 합니다. 따옴표 안의 쉼표는 필드 안에 보존됩니다. 첫 줄도 결과 행인가요? 아니요, 헤더입니다.

## json-to-csv
- **소개와 원리:** JSON 객체 배열의 키를 CSV 헤더로 만들고 각 객체 값을 행으로 씁니다.
- **활용과 절차:** 객체 배열을 스프레드시트로 옮기려면 JSON을 붙여넣고 실행합니다.
- **예제:** `[ {"name":"Mina, Joon","active":true} ]`는 쉼표가 포함된 이름을 따옴표로 감싼 CSV 행으로 출력합니다.
- **결과 해석:** 쉼표, 줄바꿈, 따옴표가 있는 필드는 CSV 규칙에 맞춰 인용됩니다.
- **제한과 FAQ:** 최상위 값은 객체 배열이어야 합니다. 단일 객체나 중첩 배열은 허용되지 않습니다. 중첩 구조도 자동 펼치나요? 아니요.

## base64
- **소개와 원리:** 인코딩은 입력 문자열을 UTF-8 바이트로 바꿔 Base64로 표현합니다. 디코딩은 Base64 바이트를 텍스트로 읽습니다.
- **활용과 절차:** 텍스트 값을 전송 형식으로 바꿀 때 인코딩을, Base64 텍스트를 읽을 때 디코딩을 선택합니다.
- **예제:** UTF-8 `Hello`는 `SGVsbG8=`로 인코딩됩니다. 한글은 UTF-8 바이트를 기준으로 변환합니다.
- **결과 해석:** Base64는 암호화나 비밀번호 보호가 아니며 데이터를 표시하는 방식입니다.
- **제한과 FAQ:** 디코딩은 Base64 텍스트와 유효한 UTF-8을 기대합니다. 비밀 값을 안전하게 숨기나요? 아니요, 누구나 다시 디코딩할 수 있습니다.

## url-encode-decode
- **소개와 원리:** 인코딩은 encodeURIComponent로 문자열을 UTF-8 기반 퍼센트 표기로 바꾸고, 디코딩은 해당 표기를 원문으로 복원합니다.
- **활용과 절차:** URL 쿼리 값의 공백, 슬래시, 비ASCII 문자를 표현하려면 인코딩을 선택해 입력합니다.
- **예제:** `hello world/한글`은 `hello%20world%2F%ED%95%9C%EA%B8%80`로 변환됩니다.
- **결과 해석:** 전체 URL 구조가 아니라 URL 구성 요소 하나를 인코딩합니다. 예약 문자는 값 안에서 퍼센트 인코딩됩니다.
- **제한과 FAQ:** 디코딩은 잘못된 퍼센트 표기나 UTF-8에서 오류가 납니다. URL 전체에 그대로 적용해도 되나요? 경로·쿼리 구성 요소별로 적용하세요.

## uuid-generator
- **소개와 원리:** 브라우저 crypto.randomUUID를 호출해 무작위 UUID v4를 줄마다 생성합니다.
- **활용과 절차:** 테스트 레코드의 고유 식별자가 필요하면 원하는 개수를 입력하고 실행합니다.
- **예제:** 3개를 요청하면 각각 36자 UUID 형식의 값이 줄바꿈으로 구분됩니다.
- **결과 해석:** 각 실행은 새 값 목록을 만들며 결과는 텍스트로 복사할 수 있습니다.
- **제한과 FAQ:** 개수는 1~100으로 제한됩니다. UUID가 중앙 서버에 등록되나요? 아니요, 브라우저의 암호학적 난수 API로 생성합니다.
