# Batch 25 Korean draft

## numbers4-number-generator
- 소개·원리: 0~9 숫자를 독립적으로 뽑아 Numbers 4 형식의 네 자리 문자열을 만듭니다. 앞자리 0과 같은 숫자의 반복을 허용합니다.
- 활용: 임의의 네 자리 조합을 연습용으로 만들고, 생성된 문자열을 복사합니다. 이는 추첨 결과 예측이나 당첨 보장이 아닙니다.
- 사용: 생성 개수 1~10을 선택하고 생성 버튼을 누릅니다. 결과에는 네 자리가 모두 보존됩니다.
- 예: 난수값을 각 자리에서 0으로 고정하면 출력은 `0000`입니다.
- 제한·문제 해결·FAQ: 매 생성은 독립 난수이므로 같은 조합이 다시 나올 수 있습니다. 11개 이상은 한 번에 요청할 수 없습니다. “앞자리가 0이면 세 자리인가요?” 아니요. 화면에서 문자열 네 자리로 유지됩니다.

## bingo5-number-generator
- 소개·원리: 공식 카드 위치별 범위에서 번호 하나씩을 생성하고 중앙은 무료 칸으로 둡니다. 행별 범위는 1–5, 6–10, 11–15, 16–20 / 중앙 무료 / 21–25, 26–30, 31–35, 36–40입니다.
- 활용·사용: 카드 한 장을 임의로 채우고 각 위치 번호가 범위에 속하는지 살펴봅니다. 생성 버튼을 누르면 한 장이 표시됩니다.
- 예: 난수를 0으로 고정하면 행 순서대로 `1, 6, 11, 16, 무료, 21, 26, 31, 36`입니다.
- 제한·주의·FAQ: 무작위 예시 카드이며 공식 추첨 예측이나 당첨 보장이 아닙니다. “중앙 숫자가 생성되나요?” 아니요. 중앙은 항상 무료 칸입니다.

## jwt-decoder
- 소개·원리: JWT의 Base64url payload를 UTF-8 JSON으로 해독하고 숫자형 `exp`를 현재 시각과 비교합니다. 서명 검증은 하지 않습니다.
- 활용·사용: 테스트 토큰을 붙여 넣고 실행해 payload와 만료 상태를 확인합니다. 민감한 실사용 토큰은 입력하지 마세요.
- 예: payload가 `{"sub":"demo","exp":2000}`이고 기준 시각이 1000ms이면 exp는 2,000,000ms이며 아직 만료되지 않은 상태입니다.
- 제한·문제 해결·FAQ: 올바른 세 부분 형식과 Base64url JSON 객체가 필요합니다. `exp`가 없거나 숫자가 아니면 만료 시각은 없다고 표시합니다. “유효한 서명인가요?” 아니요. 토큰의 신뢰성이나 서명을 검증하지 않습니다.

## url-query-parameter-parser
- 소개·원리: 전체 URL 또는 쿼리 문자열을 URLSearchParams로 읽어 키와 값 쌍을 순서대로 표시합니다. 같은 키의 반복과 빈 값도 보존합니다.
- 활용·사용: 추적 링크나 API 요청 URL을 넣어 실제 전달되는 매개변수를 확인합니다.
- 예: `https://example.test/p?a=1&a=2&empty=`는 `a 1`, `a 2`, `empty`(빈 값) 세 행을 냅니다.
- 제한·문제 해결·FAQ: `&`와 `=`는 구분자로 해석되며, 퍼센트 인코딩은 URL 규칙에 따라 해석됩니다. “반복 키는 합쳐지나요?” 아니요. 각 쌍을 별도 행으로 유지합니다.

## user-agent-parser
- 소개·원리: 입력 User-Agent 문자열에서 정해진 패턴을 찾아 브라우저, 버전, 운영체제, 모바일 여부를 로컬에서 추정합니다.
- 활용·사용: 테스트 환경에서 수집한 샘플 문자열을 넣고 규칙 기반 분류 결과를 확인합니다.
- 예: `Chrome/122.0.0.0`과 `Windows NT 10.0`을 포함하고 Mobile 표식이 없는 샘플은 Chrome 122.0.0.0, Windows, 모바일 아님으로 분류됩니다.
- 제한·문제 해결·FAQ: UA는 위장되거나 토큰 구성이 달라질 수 있고 최신 브라우저를 완벽히 식별하지 않습니다. “기기 정체를 확정하나요?” 아니요. 문자열 표식에 따른 참고용 추정입니다.
